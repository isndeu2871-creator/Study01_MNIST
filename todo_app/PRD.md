# 할 일 관리 앱 PRD

| 항목 | 내용 |
| --- | --- |
| 문서 상태 | 초안 v0.1 |
| 작성일 | 2026-10-01 |
| 대상 사용자 | 본인 1명 (개인용) |

## 1. 배경과 목표

하루 10~20개의 할 일을 가볍게 관리하는 개인용 웹 앱이 필요하다.
설치나 로그인 없이 브라우저에서 바로 열고, 새로고침해도 데이터가 남아야 한다.

**목표**
- 할 일을 3번 이내의 동작으로 추가·완료할 수 있다.
- 오늘 얼마나 끝냈는지 한눈에 본다.
- 순수 자바스크립트만으로 만들어 유지보수가 쉽다.

**비목표 (이번 범위 밖)**
- 로그인, 계정, 서버 동기화
- 여러 기기 간 데이터 공유
- 알림, 반복 일정, 마감일 캘린더
- 협업·공유

## 2. 사용자와 시나리오

개인 사용자 1명이 하루 중 여러 번 열어본다.

1. 아침에 오늘 할 일 10~20개를 입력하고 카테고리를 고른다.
2. 낮 동안 끝낸 일을 체크한다.
3. 진행률을 보고 남은 일을 확인한다.
4. 브라우저를 닫았다가 다시 열어도 목록이 그대로 있다.

## 3. 기능 요구사항

### 3.1 할 일 CRUD (필수)

| ID | 요구사항 | 인수 기준 |
| --- | --- | --- |
| F1 | 할 일 추가 | 텍스트를 입력하고 Enter 또는 추가 버튼을 누르면 목록 맨 아래에 생긴다. 빈 문자열(공백만 포함)은 추가되지 않는다. |
| F2 | 할 일 수정 | 항목을 더블클릭하거나 수정 버튼을 누르면 입력칸으로 바뀐다. Enter로 저장, Esc로 취소한다. 저장 시 빈 문자열이면 저장되지 않는다. |
| F3 | 할 일 삭제 | 삭제 버튼을 누르면 즉시 사라진다. 실수 방지를 위해 확인창을 한 번 띄운다. |

### 3.2 완료 체크 (필수)

| ID | 요구사항 | 인수 기준 |
| --- | --- | --- |
| F4 | 완료 토글 | 체크박스를 누르면 완료/미완료가 바뀐다. 완료 항목은 취소선과 흐린 색으로 표시한다. |

### 3.3 카테고리 (필수)

| ID | 요구사항 | 인수 기준 |
| --- | --- | --- |
| F5 | 카테고리 지정 | 추가할 때 **업무 / 개인 / 공부** 중 하나를 고른다. 기본값은 업무다. |
| F6 | 카테고리 변경 | 수정할 때 카테고리도 바꿀 수 있다. |
| F7 | 카테고리 필터 | 상단 탭(전체 / 업무 / 개인 / 공부)을 누르면 해당 카테고리만 보인다. 카테고리마다 색 배지를 붙인다. |

### 3.4 진행률 (필수)

| ID | 요구사항 | 인수 기준 |
| --- | --- | --- |
| F8 | 전체 진행률 | "완료 N / 전체 M (P%)" 글자와 진행률 막대를 화면 상단에 보인다. 할 일이 0개면 0%로 표시한다. |
| F9 | 카테고리별 진행률 | 선택한 탭의 진행률도 함께 보인다. 항목을 체크·추가·삭제할 때 바로 갱신된다. |

퍼센트는 반올림해서 정수로 표시한다.

### 3.5 있으면 좋은 기능 (선택)

- 완료 항목 일괄 삭제 버튼
- 키보드만으로 추가·체크
- 다크 모드

## 4. 비기능 요구사항

| 항목 | 기준 |
| --- | --- |
| 실행 환경 | 최신 Chrome, Edge, Safari, Firefox. 파일을 열거나 정적 호스팅(GitHub Pages)만으로 동작한다. |
| 기술 | 단일 HTML 파일 하나에 HTML, CSS, 순수 JavaScript를 모두 담는다. 외부 라이브러리와 빌드 도구를 쓰지 않는다. |
| 데이터 보존 | 새로고침과 브라우저 재시작 후에도 유지한다 (`localStorage`). |
| 성능 | 항목 100개까지 조작 지연을 느끼지 않는다. 변경은 즉시 저장한다. |
| 오류 대응 | 저장된 데이터가 깨져 있으면 빈 목록으로 시작하고 앱이 멈추지 않는다. |
| 접근성 | 체크박스·버튼에 라벨을 붙이고 키보드로 조작할 수 있다. |
| 화면 | 모바일 폭(360px)에서도 가로 스크롤 없이 쓴다. |

## 5. 데이터 모델

`localStorage` 키 하나(`todos`)에 JSON 배열로 저장한다.

```json
[
  {
    "id": "k3j2h1",
    "text": "주간 보고서 작성",
    "category": "업무",
    "done": false,
    "createdAt": 1790000000000
  }
]
```

| 필드 | 형식 | 설명 |
| --- | --- | --- |
| id | 문자열 | 고유값. 수정·삭제의 기준 |
| text | 문자열 | 할 일 내용 (앞뒤 공백 제거) |
| category | `업무` / `개인` / `공부` | 카테고리 |
| done | 불리언 | 완료 여부 |
| createdAt | 숫자 | 생성 시각 (밀리초). 목록 정렬 기준 |


단일 페이지 하나로 구성한다.

## 7. 파일 구조

단일 파일로 만든다.

```
todo_app/
  index.html   화면, 스타일, 스크립트 전부
```

`<script>` 안은 저장·불러오기, 상태 변경(추가·수정·삭제·토글), 화면 그리기, 이벤트 연결 네 부분으로 나눈다.

## 8. 성공 기준

| 항목 | 기준 |
| --- | --- |
| 기능 | F1~F9가 모두 인수 기준을 통과한다. |
| 보존 | 항목 20개를 넣고 새로고침·브라우저 재시작 후에도 모두 남는다. |
| 진행률 | 15개 중 7개 완료 시 47%로 표시된다. |
| 오류 | `localStorage`의 `todos`를 깨진 문자열로 바꿔도 앱이 열린다. |
| 환경 | 외부 요청 없이 동작한다. |

## 9. 열린 질문

1. 날짜별로 나눌 것인가, 아니면 하루 단위로 목록을 비울 것인가? (현재안: 날짜 구분 없이 계속 누적, 완료 항목 일괄 삭제로 정리)
2. 정렬은 입력 순서면 충분한가, 미완료 우선이나 카테고리순이 필요한가? (현재안: 입력 순서)
3. 삭제 확인창이 번거로우면 "실행 취소"로 바꿀 것인가?
4. 카테고리를 3개로 고정할 것인가, 나중에 사용자가 추가할 수 있게 할 것인가? (현재안: 3개 고정)
5. 데이터 백업(JSON 내보내기·가져오기)이 필요한가? 브라우저 데이터를 지우면 목록도 사라진다.
