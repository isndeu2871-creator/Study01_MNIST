# web_version

브라우저에서 도는 웹 버전. **외부 라이브러리를 쓰지 않는다.**
순전파와 전처리를 직접 구현했고, 빌드 도구도 없다. 파일을 그대로 올린다.

## 실행

`file://` 로 열면 안 된다. `fetch` 가 막혀 가중치를 못 읽는다. 간단한 서버를 띄운다.

```
cd web_version
python3 -m http.server 8000
```

그다음 브라우저에서 http://localhost:8000 을 연다.
검사는 http://localhost:8000/검증.html 이다.

## 파일

| 파일 | 하는 일 |
| --- | --- |
| `index.html` | 화면. **맨 위에 학번과 이름이 보여야 한다.** |
| `스타일.css` | 화면 꾸미기 |
| `그림판.js` | 마우스·손가락으로 그리는 칸 (280×280, 붓굵기 24 — 데스크톱과 같다) |
| `전처리.js` | `preprocess.py` 의 3단계를 옮긴 것 |
| `모델.js` | `model.py` 의 순전파를 옮긴 것 |
| `앱.js` | 위 셋을 이어 붙여 화면에 연결 |
| `검증.html` | 파이썬 결과와 대조하는 검사 페이지 |
| `가중치.bin`, `가중치정보.json` | `desktop_version/가중치내보내기.py` 가 만든 것 |
| `검증데이터.json` | `desktop_version/검증데이터만들기.py` 가 만든 것. 용량이 커서 깃에 넣지 않는다 |

## 가중치.bin 형식

float32(리틀 엔디언) 숫자를 이어 붙인 것뿐이다. 머리말이 없다.
어디부터 어디까지가 어떤 텐서인지는 `가중치정보.json` 의 `텐서` 목록이 말해 준다.

```json
{ "이름": "합성곱1.weight", "형상": [32, 1, 3, 3], "위치": 0, "개수": 288 }
```

`위치` 는 바이트 단위, `개수` 는 숫자 개수다. 읽을 때는 이렇게 한다.

```js
new Float32Array(버퍼, 항목.위치, 항목.개수)
```

순서는 파이썬이 계산하는 순서와 같다.
합성곱1 → 합성곱2 → 전결합1 → 전결합2, 각각 weight 다음 bias.

## 파이썬과 맞춰야 할 지점

| 지점 | 값 | 어디에 |
| --- | --- | --- |
| 획 기준 밝기 | 0.08 | `전처리.js` 의 `획기준`, `preprocess.py` 의 `획기준` |
| 숫자 칸 | 20 | 양쪽 `숫자칸` |
| 정규화 | 평균 0.1307 / 표준편차 0.3081 | `가중치정보.json` 을 거쳐 읽는다. 직접 적지 않는다 |
| 반올림 | `floor(x + 0.5)` | `Math.round` 를 쓰지 않는다. 파이썬 `round` 와 다르다 |
| 붙이는 위치 | `(28 - 새너비) >> 1` | 파이썬의 `//` 와 같다 |

**일부러 다른 곳이 한 군데 있다.** 파이썬은 PIL 의 LANCZOS 로 줄이는데
브라우저에서 그것을 그대로 재현할 수 없다. 그래서 면적 평균으로 줄인다.
캔버스의 `drawImage` 로 줄이지 않는 이유는 브라우저마다 결과가 달라지기 때문이다.
이 차이 때문에 검사 1(순전파)은 파이썬이 전처리한 입력으로 하고,
전처리까지 포함한 확인은 검사 2(전체 정확도)로 따로 한다.

## 검사 절차

1. `desktop_version` 에서 `python3 검증데이터만들기.py`
2. 여기서 서버를 띄우고 `검증.html` 을 연다
3. 검사 1(순전파 일치, 최대 절대차 1e-4 이하)과
   검사 2(전체 정확도 97% 이상)가 모두 **통과**여야 한다

## 배포

GitHub Pages 는 `gh-pages` 브랜치의 뿌리를 내보낸다.
이 폴더의 내용이 그 브랜치의 뿌리가 되도록 올린다.

```
git subtree push --prefix web_version origin gh-pages
```

`.nojekyll` 이 있어야 한다. 없으면 Jekyll 이 파일 이름을 건드린다.
